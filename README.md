三个 app 的共同点：

- 可安装的网页应用：在 iPhone 的 Safari 里打开网址，用“添加到主屏幕”装到桌面。每个要分别打开、分别添加。

- 成功安装缓存后可以离线打开；联网重新加载时优先获取新版。从后台切回不一定会重新加载，请核对页面版本号。

## 第一次上线（自己动手的做法）

GitHub 网页上的按钮名称可能会变，意思对得上即可。

1. 登录 GitHub，新建一个仓库（New repository），名字填 `health-route`，选 Public。
2. 进入仓库，点 Add file → Upload files，把最外层的 6 个文件一起选中上传，点 Commit changes。
3. 再点 Add file → Upload files，把整个 `study` 文件夹和整个 `money` 文件夹拖进去上传。在手机上拖不了文件夹时，改用 Add file → Create new file，文件名填 `study/index.html` 这样带斜杠的名字，GitHub 会自动建文件夹。
4. 进入仓库的 Settings → Pages，Source 选 Deploy from a branch，Branch 选 `main` 和 `/ (root)`，保存。
5. 等一两分钟，在 iPhone 的 Safari 里打开上面表格里的网址，点分享按钮，选“添加到主屏幕”。

## 以后更新

更新就是把仓库里的旧文件换成新文件，手机上的 app 不用删、不用重装，内容也不受影响。

1. 更新前先导出对应App备份，确认保存到iPhone“文件”。理财记账预算与交易练习需分别备份。本次仅更新money中的index.html、sw.js和全部practice/home运行文件，不改健康或学习。
2. 在 GitHub 仓库页面进入对应的位置：健康航线在最外层，学习航线要先点进 `study` 文件夹，理财航线要先点进 `money` 文件夹。
3. 点 Add file → Upload files，在对应目录上传新版 `index.html` 和 `sw.js`，同名文件会被替换，点 Commit changes。三个目录分别处理，不能把三个同名文件都传到根目录。
4. 等网站发布完成，保存好未完成输入并重新加载。核对页面最底部版本：健康1.0.2、学习1.2.0、理财1.2.0。仅从后台切回不一定触发重新加载；未变化时稍后再重开核对，不要删App。

## 健康航线的记录格式

```json
{
  "app": "health-route",
  "format": 1,
  "goal": { "type": "sleep", "bedTarget": "23:30", "nights": 5 },
  "days": {
    "2026-10-03": { "date": "2026-10-03", "bed": "23:20", "wake": "07:00", "exMin": 30, "exType": "跑步", "weight": 67.4 }
  }
}
```

每天一条，`bed` 和 `wake` 是入睡和起床时间，`exMin` 是运动分钟，`weight` 的单位是 kg。睡眠按起床那天记。

## 学习航线的方法和记录格式

app 不讲内容，它带着走流程：

1. 先回想：不看资料，先写下记得什么或猜它是什么。
2. 带着问题学：定一个问题，限时学 10 到 12 分钟。
3. 自己讲一遍：合上资料，用自己的话写它是什么、为什么需要、一个例子。
4. 找缺口：写下它不是什么，把说不清的地方写成一个问题。
5. 隔天再讲：过一天以后不看笔记再讲一次，之后按 1、3、7、14、30、60 天复习。

一个概念算学完，要过四关：说清、举例、划界、隔天还讲得出。一个技能算练完，要有 3 次带目标、带反馈的练习。

```json
{
  "app": "study-route",
  "format": 1,
  "units": [
    {
      "id": "x1", "start": "2026-10-04", "closed": false,
      "concept": { "name": "机会成本", "what": "…", "why": "…", "example": "…", "notThis": "…", "gap": "…",
                   "firstSaid": "2026-10-04", "recalledOn": "2026-10-05", "box": 1, "due": "2026-10-08" },
      "skill": { "name": "…", "reps": [ { "date": "2026-10-04", "goal": "…", "did": "…", "miss": "…", "fb": "对照范例", "next": "…" } ] }
    }
  ],
  "log": [ { "id": "x2", "date": "2026-10-04", "kind": "concept", "title": "机会成本", "min": 22 } ],
  "books": [ { "id": "x3", "title": "…", "status": "reading" } ],
  "goals": [ { "id": "x4", "text": "…", "done": false } ]
}
```

`units` 里一项是一轮学习（一个概念加一个技能）。`box` 是复习到第几档，`due` 是下次复习的日期。示例里的内容都是编的。

## 理财航线的方法和记录格式

app 只管预算和存钱，不提供投资建议。

1. 先存后花：收入减掉这个月要存的，剩下的是可花额度。
2. 固定支出先预留：标成“固定”的分类（比如房租）先从额度里扣掉，剩下的是日常额度。
3. 给分类定上限。
4. 看速度：比较“日常已花占日常额度的比例”和“这个月过了多少”。
5. 每周对一次账：把某一类的已花改成账单上的数，app 会补一笔“对账”记录。

月底的结果按“收入减支出”算，只和记下来的支出一样准。

```json
{
  "app": "money-route",
  "format": 1,
  "currency": "CNY",
  "unit": "cents",
  "plans": {
    "2026-10": { "income": 700000, "save": 200000, "copied": false,
                 "cats": [ { "id": "x1", "name": "房租", "cap": 150000, "fixed": true },
                           { "id": "x2", "name": "吃饭", "cap": 150000, "fixed": false } ] }
  },
  "entries": [ { "id": "x3", "date": "2026-10-04", "cat": "x2", "amt": 3550, "adj": false } ]
}
```

金额全部用“分”存（整数），`700000` 就是 7000 元，这样加起来不会有小数误差。`plans` 按月存计划，新的一个月会自动沿用上个月的。`entries` 里 `adj` 为 true 的是对账时补的差额，可以是负数。示例里的数字都是编的。


## 备份与兼容规则（本次补充）

- 本源码压缩包只含程序和虚构的测试数据，不含你手机里的健康、学习或收支记录。三个 App 仍分别导出用户备份。
- 健康、理财备份继续使用 `format: 1`。学习 1.1.0 起使用 `format: 2`，包含工作台、原有记录与草稿，仍支持导入旧格式 1。1.2.0 接受没有新可选字段的旧工作台；带补记记录或新枚举的备份应使用 1.2.0 或更新版本读取。金额仍以整数分存储，币种仍为人民币。
- 学习备份和主存储新增可选 `draft`。旧版单独保存在 `study-route.draft` 的草稿会被读取；第一次成功保存后与主记录一起写入 `study-route.v1`，然后尽力清理旧草稿键。旧版 App 不支持恢复新备份里的草稿。
- 导入前，App 将当前内容保存到 `<主键>.beforeImport`。可用“导出导入前副本”找回；它仍在本机，下一次导入会覆盖，因此重要内容应另存到“文件”。这不是一键完全回滚：导入仍按下面的合并规则执行，不会自动删除后来新增的内容。
- 健康同一天以备份为准，现有主目标保留。
- 学习同编号以备份为准，但当前草稿关联的学习轮次保留。当前与备份都有草稿时先提示冲突，不覆盖任意一份。仅保留一个当前学习轮次，优先使用草稿所属轮次。
- 理财同月计划以备份为准，但现有账目引用的其他分类保留；支出按 ID 去重。同 ID 但日期/分类/金额/对账属性不同时拒绝导入，请维护者协助核对。
- 错误格式、金额单位、重复/异常 ID 或缺失分类关联的备份会拒绝；如果历史文件本来就存在坏数据，请把文件交给维护者修复，不要手改金额单位强行导入。
- 本机主数据无法解析时暂停写入，使用“导出原始数据”保存恢复文件后联系维护；原始恢复文件不一定是可直接导入的正常备份。
- 单个导入文件上限为 8 MB。当前副本无法写入时会停止导入。
- “上次导出”记录的是生成/交给系统分享的时间；仍需自己确认文件确实保存在外部位置。

## 学习工作台 1.2.0

第一版同时维护一个当前项目和一个下一步任务。八个页面是：现在、下一步、路线、记录、证据、问题、老师、接手。详细数据结构、页面结构和范围见 [第一版设计](docs/study-workspace-v1.md)。

原有学习练习、用时、概念库和书单可在“记录”页的折叠区继续使用。工作台从用户创建或在“备份与导入学习方案”载入开始，不自动填入个人学习经历。

任务产出会保存为快照和默认“尚未核对”的证据。完成练习不会自动增加掌握自评；换任务时保留已有产出。老师偏好和当前上下文可复制或导出 Markdown 交给 GPT，App 不会自动调用模型或发送记录。

“记录”页可以补记在 GPT 或其他地方发生的学习：实际日期、做了什么、原话、做到的事、困难、下次任务和来源分别保存，不改变当前任务或掌握程度。列表按实际学习日期排序。任务可附材料、重点、操作步骤和注意事项；项目可单独记录还缺什么证据。

接手文档保留补记来源、任务材料与提示、缺失证据和顺延规则。若看过示范，注明有提示；若提示情况未记录，证据可标为“完成方式待核对”。每次结束留下“做到了什么、卡在哪里、下次只做什么”，不根据自述自动验证结论。学习按实际进度推进，不设固定结束日期。

学习格式 2 备份中的工作台会整体替换现有工作台，确认区域明确说明替换范围；原有自由练习按原规则合并。导入旧格式 1 不修改现有工作台。所有导入仍先保存本机副本。

## 投资账本（invest/，2.0.0）

单文件 app：`invest/index.html`，离线脚本 `invest/sw.js`，存储键 `invest-book.v1`，导入前副本 `invest-book.v1.beforeImport`。不联网取行情，不连接任何基金或证券账户，不提供投资建议。2.0 改成底部四个页面，数据格式向下兼容（1.x 的备份可以直接导入）。

- 账本：总资产（各基金最近一次更新的市值合计；还没填市值时先显示累计投入）、今日定投入口、财务自由度（总资产 ÷ 自由目标）、账户概览、我的持仓（占比条、每只的市值和收益、截图更新）、资产走势（每次更新市值记一个点 `history`）。
- 账户概览：年初金额和年初本金由用户填，或取去年最后一个 `history` 点；增长金额 = 现在 − 年初；今年赚的 =（现在 − 本金）−（年初 − 年初本金）；年度收益率 = 今年赚的 ÷ 年初金额（年初是 0 时 ÷ 今年投入）；资产增长率 = 增长金额 ÷ 年初金额。
- 定投：已定投天数（从设置里的开始日期或第一笔记录算）、年度/本月/本周投入、定投笔数、月度和年度目标圆环、每月投入柱状图、定投日历（按当天倍数深浅）、按天分组的记录。
- 计算器（深色）：PE-TTM（选填，只用来显示估值区间，不影响金额）、基准高点、当前点位，点“开始计算”保存并算出回撤、基础金额、倍数、档位和今日定投金额；回撤 =（高点 − 点位）÷ 高点；按规则表找档位倍数；“跟着回撤多投”的基金金额 = 基础金额 × 倍数，取整到元，超过限购按上限；固定金额的基金不乘倍数。点“按这个投了，记下来”记下所有基金，同时把当天的点位、高点、倍数存进 `days`，供“定投复盘”使用。下面的金字塔图高亮当前档位。周末只给下个交易日的参考。
- 规则表 `tiers` 是 `[回撤起点%, 倍数]` 的数组，第一档必须从 0 开始；估值区间 `peCuts` 每个指数四个从小到大的分界线。两者程序自带的都是示例，由用户自己改。
- 备用金：用户填一次余额，之后每记一笔自动扣掉，用来算“还够约几个交易日”。
- 用截图更新持仓：用户在 iPhone 上用实况文本（快捷指令“从图像中提取文本”→“拷贝至剪贴板”，或相册里全选拷贝）把持仓页截图变成文字，回到账本页点“截图更新 → 粘贴截图文字”。程序按基金名称分段，在每段里找“资产/持有金额”“持仓收益/持有收益”“收益率”前后的数字，用户核对、可改，确认后写入：市值 = 资产，持仓成本 `cost` = 资产 − 持仓收益，`snapTs` = 确认时间；截图里写的“单日累计购买上限”可选同时设成限购。截图本身不会进 app，也不会上传。
- 有了 `cost` 之后：收益 = 市值 − cost（等于平台显示的持仓收益）；累计投入 = cost + 之后记的买入；“开始前已投本金”不再参与计算。还在确认中的买入截图里没有，下次截图会补上。

备份格式：`{ app: "invest-book", format: 1, currency: "CNY", unit: "cents", data: { indices, tiers, funds, entries, skipped, cash, goal, slogan, startDate, goalMonth, goalYear, yearStart, pe, peCuts, history, days } }`。金额全部是整数分，点位和 PE 是小数。2.0 新加的字段都可以没有。导入时设置换成文件里的，记录、`days` 和 `history` 合并。
